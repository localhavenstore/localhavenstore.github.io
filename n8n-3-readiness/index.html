free n8n 3.0 check

Will your n8n workflows still run on 3.0? A free written check

Send one export file. We run a copy of every workflow on your version and on the n8n 3.0 release candidate, in locked test containers without internet, and send you a short written report. The first 10 reports are free; after that there is a waiting list.

What you get

  • One verdict: SAFE, PARTLY TESTED, DO THIS FIRST or WAIT.
  • For every workflow that fails or behaves differently on 3.0: which step, and what to do first.
  • Fix steps where we have tested them ourselves (for example: replacing the removed Function nodes).
  • A plain list of what the check could not cover.

This is a part of a real report from our rehearsal with a made-up client ("Demo Bakery", three workflows):

## n8n (2.41.5 -> 3.0 release candidate of 5 Oct 2026)

**WAIT**

What to do:
1. Do not update yet: Old stock alert [wfBakeryLegacy02]: the run fails on 3.0 release candidate of 5 Oct 2026 but works on 2.41.5
2. Do not update yet: Old stock alert [wfBakeryLegacy02]: Start, Fn fail on 3.0 release candidate of 5 Oct 2026 but work on 2.41.5
3. Do not update yet: Old stock alert [wfBakeryLegacy02], Fn: node type function is on the removed list

What we checked:
- 3 workflow(s) from your export run on throw-away copies of n8n 2.41.5 and 3.0 release candidate of 5 Oct 2026, step by step (3 step(s) compared)

How to fix what was found (only steps we tested ourselves):

- Function and Function Item nodes are removed in n8n 3.0 (n8n 2.42.6 already refuses to import or save workflows that have them). Replace each with a Code node: Function becomes mode "Run Once for All Items", Function Item becomes "Run Once for Each Item".
- In the Code node, write $input.all() where the old node used items, and $json.field where a Function Item used item.field. We ran these replacements on n8n 2.42.3 and 2.42.6 on a test server (9 Oct 2026): same output as the old node.
- Work on a copy: duplicate the workflow, replace the node, run both with the same test data and compare the output. Only then delete the old node.
- The full table of old and new lines (free): (link to our free guide)

Not covered by this check:
- Fetch web orders [wfBakeryOrders03]: 2 step(s) not tested - they failed on both versions (usually a step that calls an outside service: the test has no network)
- One test run per workflow, without network; your live n8n was not touched.
- The n8n image we tested is the 3.0 release candidate of 5 Oct 2026 (image tag v3-rc-20261005); it reports its own version as 2.42.0.
- PostgreSQL: you did not tell us your version, so its end-of-life date was not checked.

How to send your workflows

  1. Make the file (read-only, it changes nothing): n8n export:workflow --all --output=workflows.json. With Docker: docker exec -u node YOUR-N8N-CONTAINER n8n export:workflow --all --output=/tmp/workflows.json, then docker cp YOUR-N8N-CONTAINER:/tmp/workflows.json .
  2. Look at the file before you send it. Do not send passwords, keys, tokens or any other secret, and no personal, customer or confidential data. The export holds the names of your saved credentials, not their passwords (we checked this on n8n 2.42.6). But a key or password that somebody once typed directly into a step is in the file, and so is any test data that was pinned to a step. Replace secrets with REMOVED and remove pinned or sample data that is personal, confidential or otherwise sensitive. Searching for words like Bearer, api_key, token, password helps to find them, but it is not a guarantee - read the file.
  3. E-mail it to localhavenstore@gmail.com with the subject n8n 3.0 check and three lines: which n8n version you run and how it is installed (Docker, npm, a hosting service); whether you use queue mode; your PostgreSQL version if you know it.

What happens with your file

  • We never log in to your n8n, your server or any account. We never ask for a password.
  • A copy of your workflows runs on both versions in test containers without internet access, so the copies cannot reach the services your workflows normally talk to. Your real n8n is not touched.
  • Triggers do not fire in the test: each workflow is started once, with the data pinned to its trigger or, if there is none, with one empty sample item.
  • Your file is automatically deleted after 35 days. The report names your workflows; we keep a copy of it, and delete that copy when you ask (write to the same address).
  • A person reads every report before it is sent. We answer in writing. No call.

What this check cannot tell you

  • Steps that call other services (HTTP requests, mail, databases) cannot run without internet. They are listed as "not tested" - never as safe.
  • It is one test run per workflow, on the 3.0 release candidate (the image n8n published as v3-rc-20261005; it reports its own version as 2.42.0). The final 3.0 can differ.
  • It is evidence for your workflows on the versions named in the report, not a guarantee.
  • Take a backup before every update, whatever the report says.

After the report

If the report finds removed nodes, you can fix them with our free guide, or have it done: blocked Function nodes rewritten and tested, on Upwork from USD 49. If you want this check before every update: monthly n8n care on Upwork, USD 55 / 109 / 199 a month - in writing, no call.
